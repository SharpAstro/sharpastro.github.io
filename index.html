Software that runs the whole night.

SharpAstro is an ecosystem of .NET libraries and applications for astrophotography — from talking to the mount and the camera, through an unattended imaging session, to stacking what came back. Built for real rigs, including the multi-telescope setups most software will not drive.

What it does

A night, end to end

Every screenshot below is the real application, driven against simulated hardware so the whole run is reproducible.

Automation

Point it at the sky and go to bed

Cool the camera to setpoint, find focus, calibrate the guider, slew, centre on a plate solve, dither, flip the meridian, refocus when the stars start to bloat, shoot flats at dawn, and park. One mount, as many optical trains as it carries.

Refocus triggers on a trend across the last 30 frames, not one bad exposure — a gust or passing haze cannot start a focus run. Backlash is inferred from every successful autofocus rather than measured separately.

Planning

Decide what is actually worth shooting

The scheduler scores catalogued targets for tonight against altitude, the moon, and your own horizon obstructions, then hands each one the slice of the night where it sits highest.

Targets that fit a single pointing are co-framed automatically — pin the Lagoon with a wide enough sensor and the Trifid comes along in the same frame. Comets are computed locally from JPL orbital elements, so their positions and brightness are live rather than a stale list.

Finding

Know where you are pointing

A GPU sky atlas over the full Tycho-2 catalogue, with constellation figures and boundaries, deep-sky overlays, live planet and comet positions, and the mount's own reticle drawn where it currently sits.

Plate solving runs against the same catalogue with no external dependency, so a frame can be solved and the mount synced without installing anything else. ASTAP and astrometry.net are supported as alternatives.

Guiding

Keep the stars round for eight hours

A built-in guider that calibrates itself, guides on a selected star, and dithers between sub-exposures — or PHD2, if that is what you already trust.

Calibration deliberately runs half an hour east of the meridian, so a German equatorial stays on one side of the pier throughout and the declination sense it learns matches the side it will image on. Calibrating west of the meridian is how a mount teaches itself to run away in Dec.

Hardware

Talk to the gear you already own

ASCOM on Windows, Alpaca over HTTP anywhere, native ZWO and QHYCCD SDKs, serial mounts including Meade LX200, SkyWatcher, OnStep and iOptron, and Canon bodies over PTP with no vendor SDK installed at all.

Devices are addressed by URI, so a driver is a string in a profile rather than a compile-time choice, and a headless Raspberry Pi runs the same code as a Windows desktop.

Remote

Watch it from somewhere warm

A headless server exposes the session over REST and WebSocket, and serves the same hardware over the ASCOM Alpaca protocol, so other software can drive it too.

A desktop can bind another node and mirror its run through the same tabs that render a local one. Selecting a rig changes what you are looking at — never what your own machine owns.

Live demo

The atlas runs in your browser

No install and no account: the planner and the sky atlas are compiled to WebAssembly and served as a static site.

Every tab in the desktop application is generic over the surface it draws on, so the same code that renders through Vulkan on a desktop renders through WebGL in a tab. It is the same scheduler, the same catalogue, and the same projection maths — not a reimplementation.

Install

The image viewer is in the Microsoft Store

Astro Photo Viewer is the suite's viewer shipped on its own: FITS, SER planetary video, TIFF and Canon CR2/CR3, with stretch and Bayer demosaic done on the GPU, star detection with HFD-sized circles, a WCS grid and catalogue annotations over a plate-solved frame, and a live lucky-imaging stack with wavelet sharpening for planetary video.

Microsoft re-signs the package during certification, so it installs with no SmartScreen warning at all and updates itself. Windows 10 version 2004 or newer, x64 and ARM64. Double-clicking a .fits, .fit, .fts, .fz or .ser opens it in the window already showing that folder.

Get it from the Microsoft Store →

Linux and macOS run the same viewer from a self-contained native AOT archive on GitHub Releases, which also carries the Windows archives for anyone who would rather not install from the Store.

The ecosystem

Nineteen pieces, each usable on its own

The astrophotography stack sits on top of general-purpose libraries that were written to support it and are independently useful. All pure-managed and AOT-friendly unless they wrap a vendor's native SDK.

Astrophotography — core

  • tianwen The imaging suite itself (天文). Device management, session automation, FITS I/O, star detection and plate solving. Ships as a NuGet library, a CLI with a terminal UI, a headless REST server, a FITS viewer and an integrated GUI.AGPL-3.0
  • TianWen.DAL Vendor-neutral device access layer: the interfaces every camera, mount, focuser and filter wheel implements.

Device SDKs & bindings

  • ZWOptical.SDK ZWO ASI cameras, EAF focusers and EFW filter wheels, with bundled natives for Windows and Linux on x86, x64 and ARM.
  • QHYCCD.SDK QHYCCD native SDK wrapper for .NET.
  • Canon.EDSDK Canon EDSDK bindings, fully source-generated and NativeAOT-compatible.
  • FC.SDK "Free Canon SDK" — Canon EOS control over PTP via USB and Wi-Fi in pure managed C#, with no Canon binary required. The option for platforms Canon does not ship for.

Formats & imaging

  • FITS.Lib FITS reader and writer, with a large speed-up for writing the big multi-dimensional integer arrays astronomical imaging actually produces.
  • SER.Lib The SER planetary video format, memory-mapped with frame-accurate random access even in multi-gigabyte captures.
  • Codecs A family of pure-managed image codecs (TIFF, PNG, JPEG, JPEG XR, OpenEXR, ICC) behind a facade that sniffs magic bytes and dispatches.

General-purpose .NET

Written for the stack above, with no dependency on it. Pure managed, trim- and AOT-friendly, MIT licensed.

  • DIR.Lib Device-independent input, rendering and layout — the declarative layout engine and widget model shared by the GPU and terminal front ends.
  • SdlVulkan.Renderer An SDL3 + Vulkan rendering surface over those primitives.
  • WebGl.Renderer The same surface for Blazor WebAssembly and WebGL2 — what draws the live demo above.
  • Console.Lib Terminal applications: dock layouts, widgets, mouse and keyboard input, a diffing cell buffer, and Sixel graphics. Also ships mdcat, a cat-for-Markdown.
  • Fonts.Lib OpenType and TrueType loading and rasterising: hinting, CFF outlines, COLR colour glyphs, bitmap emoji, variable fonts, Type 1, and WOFF/WOFF2.
  • Lzip.Lib lzip (LZMA1) compression and decompression, including parallel decode of multi-member files, byte-compatible with the reference tool.
  • LAN.Lib Local-network discovery and peer tracking — how a node finds the other rigs on the network.
  • LALR.CC An LALR(1) parser-table generator and runtime for C#, with a YAML grammar schema and a Roslyn source-generator pipeline.

Utilities

  • openphd2-multiscope A multiplexing proxy for PHD2's JSON-RPC API, so several telescopes dither in step.
  • usbreset Resets a wedged USB device without a physical replug — for the camera that stops answering at 3am.
