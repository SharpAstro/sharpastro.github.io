Software that runs the whole night.

SharpAstro is a set of open-source .NET libraries and applications for astrophotography. It covers the whole night: controlling the mount and camera, running an unattended imaging session, and stacking what comes back. It's built for real rigs, including the multi-telescope setups most software can't drive.

What it does

A night, end to end

Every screenshot below is the real application. The session tabs were captured against simulated hardware, so anyone can reproduce the run, and the viewer is showing a real stack.

Automation

Point it at the sky and go to bed

It cools the camera, finds focus, calibrates the guider, slews and centres on a plate solve, dithers, handles the meridian flip, refocuses when the stars start to bloat, shoots flats at dawn, and parks. It drives one mount and every optical train on it.

Refocusing is triggered by a trend over the last 30 frames rather than one bad exposure, so a gust of wind or passing haze won't start a focus run. Focuser backlash is worked out from every successful autofocus, so you never have to measure it separately.

Planning

Decide what is actually worth shooting

The scheduler ranks tonight's targets by altitude, the moon, and whatever blocks your own horizon, then gives each one the part of the night when it's highest.

Targets that fit in one field of view are framed together automatically. Pin the Lagoon with a wide enough sensor and the Trifid comes along for free. Comet positions and brightness are calculated locally from JPL orbital elements, so they're always current instead of coming from a list that has gone stale.

Finding

Know where you are pointing

A GPU-rendered sky atlas of the full Tycho-2 catalogue, with constellation figures and boundaries, deep-sky overlays, live planet and comet positions, and a reticle showing where the mount is pointing right now.

The plate solver uses the same catalogue and needs nothing else installed, so you can solve a frame and sync the mount out of the box. ASTAP and astrometry.net work too, if you prefer them.

Guiding

Keep the stars round for eight hours

The built-in guider calibrates itself, guides on the star you pick, and dithers between sub-exposures. If you already trust PHD2, use that instead.

Calibration runs half an hour east of the meridian on purpose. That keeps a German equatorial mount on one side of the pier the whole time, so the declination direction it learns matches the side it will image on. Calibrating west of the meridian is how a mount ends up running away in Dec.

Hardware

Talk to the gear you already own

ASCOM on Windows, Alpaca over the network on any platform, the native ZWO and QHYCCD SDKs, serial mounts such as Meade LX200, SkyWatcher, OnStep and iOptron, and Canon bodies over PTP without installing any Canon software.

Each device is identified by a URI, so switching drivers means editing a profile, not rebuilding anything. A headless Raspberry Pi runs exactly the same code as a Windows desktop.

Remote

Watch it from somewhere warm

Run it headless and the session is available over REST and WebSocket. The same hardware is also served over ASCOM Alpaca, so other software can drive it too.

From a desktop you can connect to another machine and follow its run in the same tabs you'd use locally. Switching to another rig changes what you're looking at, not what your own machine is controlling.

Inspecting

Look at what came back

Astro Photo Viewer is the suite's image viewer as a standalone app, available from the Microsoft Store. It opens FITS, SER planetary video, TIFF and Canon CR2/CR3 files, stretches and debayers them on the GPU, measures every star it finds, and overlays a coordinate grid and catalogue labels on a plate-solved frame.

SER files open in playback mode. A RAW/STACK toggle switches to a rolling lucky-imaging stack that follows the playhead, with six wavelet sharpening sliders on top. Stacking runs in the background, so the sliders stay responsive however long a stack takes.

Get it from the Microsoft Store → User guide →

Needs Windows 10 version 2004 or newer, on x64 or ARM64, and updates itself through the Store. Double-clicking a .fits, .fit, .fts, .fz or .ser file opens it in the window that's already showing its folder, instead of starting another copy. On Linux and macOS, the same viewer is a self-contained native download on GitHub Releases.

Live demo

The atlas runs in your browser

Nothing to install and no account needed. The planner and sky atlas are compiled to WebAssembly and run straight from a static site.

The desktop app's tabs don't care what they draw on, so the code that renders through Vulkan on your desktop renders through WebGL in a browser tab. Same scheduler, same catalogue, same projection maths. It isn't a port.

The ecosystem

Twenty pieces, each usable on its own

The astrophotography stack is built on general-purpose libraries that were written for it but are useful on their own. Everything is pure managed code and AOT-friendly, except where it wraps a vendor's native SDK.

Astrophotography — core

  • tianwen The imaging suite itself (天文): device management, session automation, FITS I/O, star detection and plate solving. Available as a NuGet library, a CLI with a terminal UI, a headless REST server, a FITS viewer and a full desktop GUI.AGPL-3.0
  • TianWen.DAL Vendor-neutral device access layer: the interfaces every camera, mount, focuser and filter wheel implements.

Device SDKs & bindings

  • ZWOptical.SDK ZWO ASI cameras, EAF focusers and EFW filter wheels, with bundled natives for Windows and Linux on x86, x64 and ARM.
  • QHYCCD.SDK A .NET wrapper for the QHYCCD native SDK.
  • Canon.EDSDK Canon EDSDK bindings, fully source-generated and NativeAOT-compatible.
  • FC.SDK The "Free Canon SDK": controls Canon EOS cameras over PTP via USB or Wi-Fi in pure managed C#, with no Canon binaries needed. Handy on platforms Canon doesn't support.

Formats & imaging

  • FITS.Lib A FITS reader and writer that's much faster at writing the large multi-dimensional integer arrays astronomical imaging actually produces.
  • SER.Lib SER planetary video, memory-mapped, with fast access to any frame even in multi-gigabyte captures.
  • Codecs Pure managed image codecs (TIFF, PNG, JPEG, JPEG XR, OpenEXR, ICC) behind a single entry point that detects the format from the file itself.

General-purpose .NET

Written for the stack above, with no dependency on it. Pure managed, trim- and AOT-friendly, MIT licensed.

  • DIR.Lib Device-independent input, rendering and layout: the declarative layout engine and widgets shared by the GPU and terminal front ends.
  • SdlVulkan.Renderer Renders DIR.Lib on the desktop through SDL3 and Vulkan.
  • WebGl.Renderer Renders DIR.Lib in the browser through Blazor WebAssembly and WebGL2. It draws the live demo above.
  • Console.Lib Terminal applications: dock layouts, widgets, mouse and keyboard input, a diffing cell buffer, and Sixel graphics. Also includes mdcat, which is cat for Markdown.
  • Fonts.Lib OpenType and TrueType loading and rasterising: hinting, CFF outlines, COLR colour glyphs, bitmap emoji, variable fonts, Type 1, and WOFF/WOFF2.
  • Lzip.Lib lzip (LZMA1) compression and decompression, including parallel decode of multi-member files, byte-compatible with the reference tool.
  • LAN.Lib Local-network discovery and peer tracking, which is how a node finds the other rigs on the network.
  • Serial.Lib Serial port I/O that reads and writes reliably, even on the cheap USB adapters where System.IO.Ports doesn't. Reads and writes can be cancelled and never hang past their deadline, failures come back as specific errors, and ports are listed with a hardware identity that stays the same between runs. It's what TianWen uses to talk to mounts and focusers.
  • LALR.CC An LALR(1) parser-table generator and runtime for C#, with a YAML grammar schema and a Roslyn source-generator pipeline.

Utilities

  • openphd2-multiscope A multiplexing proxy for PHD2's JSON-RPC API that keeps several telescopes dithering in step.
  • usbreset Resets a stuck USB device without unplugging it. For when the camera stops responding at 3am.
